# Model evaluation tracker

Shared status board for downloading, configuring and benchmarking candidate
models for the llama.cpp router. Several agents work from this file: claim a
row before starting it, update it as you go, and never edit a row someone else
has claimed except to add a note.

Goal: more concurrent requests. Prefer models of 12B parameters or less that
fit several slots of at least 64k context, and keep the best agentic quality.
Baseline for comparison: `qwen-3.6-35b-a3b` (current Hermes model, 1 slot × 128k).

## Rules

- Presets follow `router-config.ini.example` conventions: `load-mode = dio`
  (from `[*]`; `mmap` only 2026-10-28 to 10-29), `fit = off`, thinking on for every chat model, MoE
  experts in RAM fit-based with `n-cpu-moe`. Keep `router-config.ini` and
  `router-config.ini.example` in sync.
- Memory budget: ~20 GiB VRAM, 15 GiB host RAM (~7 GiB used by other stacks),
  4 GiB swap.
- One model is loaded at a time; run loads and benchmarks sequentially and
  mark the row `benchmarking` while it holds the router.
- Record measured numbers only; leave a cell empty rather than estimating.
- Status values: `todo`, `claimed`, `downloading`, `configured`,
  `benchmarking`, `done`, `blocked` (say why in Notes), `dropped`.
